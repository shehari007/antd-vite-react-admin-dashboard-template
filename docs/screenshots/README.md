# Screenshots

These are the images shown in the main README. They are generated by
[`capture.mjs`](capture.mjs) rather than taken by hand, so a release never ships
with screenshots of the previous version.

| File                  | What it shows                                                         |
| --------------------- | --------------------------------------------------------------------- |
| `dashboard-light.png` | `/dashboard/home` in light mode, sidebar expanded                     |
| `dashboard-dark.png`  | The same route in dark mode, so the pair lines up exactly             |
| `charts.png`          | `/dashboard/charts` in dark mode, where the themed tooltips read best |
| `command-palette.png` | The palette opened with a real Ctrl+K, mid search                     |
| `products.png`        | The service layer page, with filters, sorting, and paging             |
| `customizer.png`      | The theme drawer open                                                 |
| `rtl.png`             | The dashboard in Arabic, layout fully mirrored                        |
| `mobile.png`          | A 414px viewport with the navigation drawer open                      |

All eight are 1440 x 900 at a device pixel ratio of 1, except the mobile shot at
414 x 896. Every file is under 160 kB.

## Regenerating them

Playwright is deliberately not a dependency of this project. It is a large
install that nobody building a dashboard needs, so it goes in and out again:

```bash
npm run build
npx vite preview --port 4190

# in a second terminal
npm i -D playwright
node docs/screenshots/capture.mjs
npm uninstall playwright
```

The script drives the Chrome already installed on your machine. If you do not
have Chrome, change `channel: 'chrome'` to `'msedge'`, or remove the option and
run `npx playwright install chromium` first.

It seeds `localStorage` before each page loads, so theme and language are set
before first paint and there is no flash of the wrong mode in the capture. It
also fails the run if the console logged an error, which means a screenshot
never quietly documents a broken page.

## Still worth adding by hand

**`public/og-image.png`**, 1200 x 630. This is what appears when the demo link
is shared on social media, and `index.html` already points at it. The dark
dashboard shot cropped to that ratio works well. Upload the same image under
Settings, General, Social preview on GitHub.

**`demo.gif`**, showing the sidebar collapsing and expanding. Record at 1280
wide, keep it to four to six seconds, and keep it under about 2 MB or it will
not finish loading before a visitor scrolls past it.
